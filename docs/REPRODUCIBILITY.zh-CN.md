## v0.2.0 发布检查

2026-10-13，在 RTX 2080 Ti 上执行的 57 项测试全部通过，其中包含八项 CUDA 测试。安装后的 wheel 在完整 fsaverage 模板上完成了两条命令行流程，并将生成的球面直接传入配准。每个输入包含 163,842 个顶点和 327,680 个三角形。两个命令均使用默认设置，配准的 `rotation_point_chunk=16384`。输出保留输入三角面，坐标均为有限值，且没有零面积三角形。

[机器可读记录](validation-v0.2.0.json)包含输入与源码摘要、依赖版本、参数和结果。这些检查验证了安装后的软件在所述模板上的运行情况，不能据此确定跨被试精度或相对官方 C 实现的加速比。另有专门的零残差回归测试覆盖 PCG 除零问题的修复。

之后补充的 [v0.2.0 基准](BENCHMARKS_v0.2.0.zh-CN.md)使用相同输入测量 CPU/GPU 完整命令，并报告与固定版本 C 参考程序的坐标差异。[JSON 记录](benchmark-v0.2.0.json)包含每次测量和具体参数。

## 记录版本与环境

使用 v0.2.0 时，请记录：

- 软件包版本与源码修订版本；
- CAT-Surface 参考提交 `b0c2aa2395ea4957a331b9444fb54c7716b6572d`；
- Python、NumPy、SciPy、Numba、nibabel、CuPy、CUDA 及驱动版本；
- GPU 型号、CPU 线程数，以及主机内存和显存峰值；
- 输入摘要、顶点/三角形数量、参数、求解器及迭代次数。

固定上游版本也记录在 [UPSTREAM.lock](../UPSTREAM.lock) 中。v0.1.0 使用不同的参考版本与实现，其证据保留在[历史性能记录](BENCHMARKS.zh-CN.md)中。

## 分层验证

1. 检查构建后的 wheel 与源码包是否包含所需代码及许可说明，并确认其中没有 CAT 可执行程序或本项目专用扩展。
2. 运行几何、索引、拓扑、插值和输入检查相关的 CPU 测试。
3. 在实际 NVIDIA GPU 上运行 CUDA 测试，单独记录跳过的测试。
4. 使用相同输入与参数，对照独立运行的参考程序，比较完整球面及配准球面的输出。

比较曲面时，应记录三角面是否精确一致，并使用明确单位报告坐标差异。至少给出最大值、平均值和一个高百分位数，同时说明误差是逐坐标的绝对差，还是逐顶点的欧氏距离。计算统计值之前，先检查坐标是否有限及顶点数是否一致。

v0.2.0 默认使用 PCG 线性求解器。上游 CAT-Surface 使用 FMG，因此相同输入与迭代参数名称并不代表相同的求解过程。应在评估结果前确定数值容差，并记录实际使用的求解器。v0.1.0 的 `1e-3` 阈值不能自动作为 v0.2.0 的验收阈值。

## 测量完整操作

报告端到端耗时时，应一起测量输入读取、预处理、数据传输、GPU 计算、输出传输和文件写入。停止计时前先同步 GPU，并说明是否计入解释器启动、Numba/CuPy 编译和缓存加载。首次运行与缓存已建立后的重复运行应分别报告。

对同一输入重复运行，报告运行次数和耗时分布。双半球运行需说明是串行执行，还是并发共享 GPU。单个计算内核的加速比不能代表完整配准流程或完整 CHARM 流程。

## 合成输入与解剖输入

本仓库不分发解剖数据或被试数据。合成测试数据用于检查安装、文件读写和小规模数值计算。非常粗的合成网格可能在完整膨胀流程中塌缩，因此应使用合适的解剖网格验证完整球面生成与配准流程。合成数据不能复现解剖数据上的性能，也不能证明解剖配准精度。

基准测试输入应保持只读。缓存、日志、参考输出和候选输出分别放在任务目录内，例如 `.work/comparison/`。运行前设置 `TMPDIR`、`TMP`、`TEMP`、`XDG_CACHE_HOME`、`NUMBA_CACHE_DIR` 和 `CUPY_CACHE_DIR`，具体示例见[中文 README](../README.zh-CN.md#run)。

上游参考程序可以单独构建和运行，用于对照。它不是候选流程的依赖，也不是自动回退路径。
