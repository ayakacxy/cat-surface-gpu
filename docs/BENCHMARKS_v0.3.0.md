# Benchmarks: v0.3.0

[English](BENCHMARKS_v0.3.0.md) · [简体中文](BENCHMARKS_v0.3.0.zh-CN.md)

Measured on 2026-10-18. The complete single-surface commands take a median **2.612 seconds** for sphere generation and **4.983 seconds** for registration on an RTX 2080 Ti. The [JSON record](benchmark-v0.3.0.json) contains individual runs, commands, input hashes and output comparisons.

## Environment and inputs

| Item | Value |
| --- | --- |
| Platform | Linux x86-64 |
| GPU | NVIDIA GeForce RTX 2080 Ti |
| CPU | Intel Xeon Gold 6230 @ 2.10 GHz |
| Python / CuPy | 3.11.15 / 14.2.0 |
| NumPy / SciPy / Numba / nibabel | 2.3.0 / 1.17.1 / 0.64.0 / 5.3.3 |
| CPU threads | 8 |
| Inputs | Public fsaverage surfaces, each with 163,842 vertices and 327,680 triangles |
| Sphere settings | `stop_at=10`, including all 4,999 area-smoothing sweeps |
| Registration settings | Two runs, averaging and initial rotation enabled, `512 × 256` map |
| Solver | PCG, 40 iterations, `pcg_check_interval=0` |
| Rotation batch size | `rotation_point_chunk=12288` |

Sphere generation uses `lh.white.gii`. Registration uses the supplied LH white/sphere pair as the source and the RH white/sphere pair as the target. The two commands are measured separately; the registration test does not use the sphere generated by the first command.

## Complete command times

Each repetition launches a new process. Timing begins at process launch and ends at exit, covering imports, input reading and checks, cache loading, computation and compressed GIFTI writing. Output comparison runs after the timer. The table reports three repetitions with populated application caches; the versions alternate order between rounds.

| Command | Median | Range |
| --- | ---: | ---: |
| Sphere generation | 2.612 s | 2.601–2.648 s |
| Registration | 4.983 s | 4.967–5.116 s |

The first sphere and registration commands took **14.050 seconds** and **11.700 seconds**, respectively. Application caches were empty before the sphere command; registration could reuse kernels compiled by it. OS file caches and driver state were not reset. First-call times are excluded from the medians.

## Output comparison

Both versions preserve triangle indices and produce finite coordinates with no zero-area triangles. Each version's output coordinates are identical across its three repeated runs.

| Difference between versions | Sphere generation | Registration |
| --- | ---: | ---: |
| Maximum absolute coordinate difference | 0.000244141 | 0.001388580 |
| Maximum vertex distance | 0.000286091 | 0.001632973 |
| Maximum angular difference | 0.000227° | 0.093562° |
| 99th-percentile angular difference | 0.000195° | 0.048106° |
| Corresponding triangle normals with a negative dot product | 0 | 34 |

Coordinates and distances use the units stored in each GIFTI file. Angular differences compare normalized vertex directions. The final row compares normals between outputs; it is not a count of independently identified inverted triangles. These geometric comparisons do not measure anatomical registration accuracy.

## Bilateral workflow

A separate test uses public fsaverage white surfaces resampled onto a 61,442-vertex mesh. Each hemisphere is inflated, upsampled to 245,762 vertices and registered. The two hemispheres run serially in one process with inputs, templates and fixed topology already loaded.

| Timing scope | Median |
| --- | ---: |
| Both hemispheres, including four completed compressed GIFTI writes | 9.731 s |
| Sum of internal sphere-generation and registration timers | 5.771 s |

The table reports medians of three warm-cache runs, excluding the first call. The first row includes setup and validation outside the internal timers. It excludes process startup, imports and preparation of the resampled inputs. Because this test uses different mesh sizes and timing boundaries, its result cannot be obtained by adding or doubling the single-surface command times above.

## Reproduce the command comparison

Install the CUDA dependencies described in the [README](../README.md). From the repository root, use the public fsaverage files or another suitable source/target pair. The baseline directory must contain the `cat_surface_gpu` package; the following example extracts it from the v0.2.0 tag.

```bash
mkdir -p .work/version-benchmark/{tmp,cache,baseline}
export TMPDIR="$PWD/.work/version-benchmark/tmp"
export TMP="$TMPDIR" TEMP="$TMPDIR"
export XDG_CACHE_HOME="$PWD/.work/version-benchmark/cache"
export PYTHONDONTWRITEBYTECODE=1

git archive v0.2.0 src | tar -x -C .work/version-benchmark/baseline

python tools/benchmark_versions.py \
  --baseline-source .work/version-benchmark/baseline/src \
  --candidate-source src \
  --source-surface /path/to/fsaverage/lh.white.gii \
  --source-sphere /path/to/fsaverage/lh.sphere.gii \
  --target-surface /path/to/fsaverage/rh.white.gii \
  --target-sphere /path/to/fsaverage/rh.sphere.gii \
  --work-dir .work/version-benchmark/results \
  --device cuda --repeats 3 --threads 8
```

The results directory must not already exist. The script assigns separate project-local caches to each version, records one first call and three repeated calls, and writes `report.json`, command logs and output surfaces. It also checks repeatability and compares output geometry. Input files are not modified.
